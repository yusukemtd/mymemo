# テキストエディタとしてあると便利な機能の調査(2026-08-29)

mymemo の現状(`src/*.js`, `src-tauri/src/*.rs`, README)を読み、「まだ無くて、あると便利な機能」を
実装コスト・依存の有無つきで洗い出したメモ。着手時の優先順位づけに使う。
2026-09-01 実装済みの項目を削除(実装済みの機能一覧は README を参照)。

## 既存の問題

1. **巨大ファイルのガードが無い**: grep は 20MB 超をスキップするが `read_file` には上限が無く、数百 MB を開くと固まる。

## 候補一覧

### A. 小さくて効く(新規依存なし・1 コミット規模)

| 機能 | なぜ便利か | 実装の当たり |
| --- | --- | --- |
| タブ操作の拡充 | タブが増えたときの移動コスト | `Cmd+1〜9` で切替、ドラッグで並べ替え、`Cmd+Shift+T` で閉じたタブを復元、中クリックで閉じる、右クリック「他を閉じる」 |
| Finder で表示 / パスをコピー | 開いているファイルの場所へすぐ行ける | Rust 側で `open -R <path>`(`std::process::Command`、プラグイン不要)。クリップボードは `navigator.clipboard` |
| grep フォルダの既定をアクティブファイルの場所に | 毎回フォルダを選ぶ手間をなくす | `grep.js` の `searchDir` 初期値をアクティブタブの `dirname` に。ルート選択は残す |
| 巨大ファイルの警告 | 固まる前に止める(上の「既存の問題 1」) | `read_file` でサイズを見て、閾値(例 50MB)超は確認 → 開く場合はハイライト・空白表示を無効化 |

### B. 中規模(新規依存なし・設計を少し要する)

| 機能 | なぜ便利か | 実装の当たり |
| --- | --- | --- |
| テキスト変換の追加 | CotEditor 等にある定番の残り。実装済みは行のソート / 重複削除 / 空行削除のみ | 大文字/小文字、全角⇄半角、ひらがな⇄カタカナ、末尾空白の削除。`transform.js` に追加し、`view.dispatch` 1 回で undo 可能 |

### C. 大きい・依存追加が要る(着手前に要相談)

| 機能 | 備考 |
| --- | --- |
| ウィンドウの位置・サイズの復元 | `tauri-plugin-window-state` を追加すれば数行。自前なら `onResized`/`onMoved` を `localStorage` に |
| 分割表示(2 ペイン) | `EditorView` を 2 つ持ち、同じ `EditorState` の共有か別タブか設計が要る。`tabs.js` が単一 view 前提 |
| 複数ウィンドウ | `tabs.js` の状態がモジュール変数なので大きめの改修 |
| フォルダを開く(ファイルツリー) | サイドバー UI と Rust 側のディレクトリ走査。grep と組み合わせると「プロジェクト」化する |
| URL / パスをクリックで開く | `tauri-plugin-opener` の追加 |
| 自動保存 | 「メモ」としてはあり。既存ファイルの自動上書きは事故要因なので、無題タブの下書き保存(セッション復元)から始めるのが安全 |
| 印刷 | `window.print()` は WKWebView で動くが、書式調整が必要 |

### Markdown 編集支援(2026-08-29 追加分)

| 残りの候補 | 実装の当たり |
| --- | --- |
| 表の整形(列幅を揃える) | 表の行を `\|` で分割し、全角 2 幅で列幅を揃える。カーソルが表の中にあるときのコマンド |
| プレビューのコードブロックのハイライト | `@codemirror/language` の `highlightTree` で HTML 化し、marked の code レンダラを差し替える |
| プレビューのスクロール同期を見出し単位に | カーソル行に最も近い見出しの順番でプレビューの `h*` へ `scrollIntoView` |
| アウトライン(見出し一覧)パネル | 構文木の `ATXHeading*` を一覧にしてクリックでジャンプ。grep パネルと同じ作り |
| 文書内リンクの補完 | `[](` の中で `#見出し` を候補にする(単語補完と同じ `autocompletion` の source) |
| Enter 継続時に下の番号も進める | `insertNewlineContinueMarkup` は上の項目しか見ないので、継続後に「番号を振り直す」を同じリストへ適用する |
